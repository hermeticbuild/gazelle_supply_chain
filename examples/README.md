# BuildBuddy: one module, two licenses

[BuildBuddy's LICENSE](https://github.com/buildbuddy-io/buildbuddy/blob/master/LICENSE)
says `enterprise/` is under `enterprise/LICENSE` and the rest is MIT. This
example imports BuildBuddy from `go.mod` with rules_go and Gazelle and tags every
generated package with the license of the subtree it lives in.

## How it works

1. `go_deps.from_file` imports `github.com/buildbuddy-io/buildbuddy` from `go.mod`.
2. `go_deps.gazelle_override` runs Gazelle with only the license language
   (`-lang=license`) and these flags, so BuildBuddy's own BUILD files are kept and
   just get one `package(default_applicable_licenses = ...)` call appended:
   - `-license_default="//_gazelle_generated:package_metadata MIT"`
   - `-license_subtree="enterprise=//enterprise:package_metadata LicenseRef-BuildBuddy-Enterprise"`
   - `-license_strict` with `-license_confidence="licensecheck=65 LICENSE"` (only for the root LICENSE): Gazelle fails if a
     LICENSE file is undeclared or doesn't contain the declared SPDX id. The root
     LICENSE is MIT plus a carve-out for `enterprise/`, which only matches MIT at
     about 67%; `enterprise/LICENSE` is custom, so it is declared with a
     `LicenseRef-` id.

   Flags are used instead of `build_directives` because `go_repository` writes
   directives over the root BUILD file.
3. `go_repository` always runs the Gazelle from `@bazel_gazelle_go_repository_tools`.
   `override_repo` replaces that repo with `gazelle_tools_with_license`
   (`../tools_repo.bzl`), a Gazelle built with the license plugin, so the
   directives take effect inside the external repo.
4. `//cmd` has two binaries plus SBOM targets for each (`*_sbom`, `*_spdx`, `*_cyclonedx`):
   - `oss_only` uses `server/util/random` -> MIT only.
   - `with_enterprise` also uses `enterprise/server/util/fieldgetter` -> enterprise license too.
5. `//cmd:mattermost` depends on Mattermost's server module (`platform/shared/mfa`), which has no BUILD files
   either. Its module zip leaves out the repository's root `LICENSE.txt`, so `MODULE.bazel` declares it as
   AGPL-3.0-only, plus a `LicenseRef-Mattermost-Enterprise` subtree for `enterprise/`. The root
   `LICENSE.enterprise` symlink is not used: it only points at `server/enterprise/LICENSE`. The SBOM reports `v8` as
   AGPL-3.0-only, with its dependencies detected from their own license files. This needs Go 1.26 (`go_sdk.download`).
6. `//cmd:license_coverage_test` asserts that mapping from the SBOM graphs and the AGPL declaration.

```
bazel test //cmd:license_coverage_test
bazel build //cmd:with_enterprise_spdx
```

## Notes

- Pinned to `v1.9.2`, the newest version served by the Go proxy used while
  writing this. It predates `cli/`. BuildBuddy's newer tags (`v2.x`) are not
  valid Go module versions (its `go.mod` has no `/v2`), so use the commit's
  pseudo-version, e.g. `v0.0.0-20261022001121-0256c04a93c1` for `v2.318.0`
  (update `go.sum` too), where `@com_github_buildbuddy_io_buildbuddy//cli/...`
  exists. Imports there need the transitive requirements in `go.mod`.
- BuildBuddy restricts the visibility of its `enterprise/` targets to its own
  workspace. Keeping their BUILD files means that restriction stays, so the
  example's `.bazelrc` sets `--check_visibility=false`.
- The license targets (`//:gazelle_generated_license`, `//enterprise:gazelle_generated_license`)
  are generated by the plugin inside BuildBuddy's own repo and appended to the
  `package_metadata` that `go_repository` generates (a new one is created for
  `enterprise/`, purl subpath `#enterprise`). Nothing is copied. A small patch fixes BuildBuddy's root `BUILD`
  (a `config/` label that doesn't load as shipped).
- The tools repo is built with the host `go`.
- The SBOM comes from a `supply-chain` branch that emits license information:
  `bazel build //cmd:with_enterprise_spdx` then read `bazel-bin/cmd/with_enterprise.spdx.json`.
  `enterprise/` is `LicenseRef-BuildBuddy-Enterprise` (its text is embedded in
  `hasExtractedLicensingInfos`) and the rest of BuildBuddy is `MIT`. The mapping
  is also in `*_sbom.graph.json` and `*_sbom.sbom-classifications.json`.
- Every other Go module gets the plugin through `go_deps.gazelle_default_attributes`
  with `-license_default="//_gazelle_generated:package_metadata detect"`, so
  gRPC, protobuf and the others carry the license read from their own LICENSE file.
